# 重采样算法选型（全部实测）

## 一、两个方向，本质不同

| 方向 | 场景 | 需要抗混叠吗 | 本板用什么 |
|---|---|---|---|
| **升采样** 22050 → 48000 | TTS 输出 → 喇叭 | ❌ 不需要（升采样不产生混叠，只需平滑） | `resample_linear`（np.interp） |
| **降采样** 48000 → 16000 | 麦克风 → ASR | ✅ **必须**（否则高频折叠毁识别） | `decimate3-mavg3` |

**这不是对称问题，不能一套算法包打天下。**

## 二、升采样：linear vs polyphase（实测）

本板 A55×4，2 秒 22050→48000：

| 算法 | 耗时 | 输出峰频 | 输出幅度 | 结论 |
|---|---|---|---|---|
| **linear（np.interp）** | **16.6 ms** | 1000 Hz ✅ | 1.000 ✅ | **选它** |
| polyphase（sinc 相位滤波） | **1776.9 ms** | 1000 Hz ✅ | 1.005 ✅ | 慢 **107 倍** |

两者质量都正确（频率保持、幅度保持），差异只在插值平滑度
（`max|linear−poly|=0.43`、`mean=0.10`，属高次谐波差异）。

**真实 TTS 语音验证**（matcha 输出 1.20s @22050 → 48k）：
```
频谱相关度 (100–7000 Hz) = 0.9997
幅度  src max=0.310  →  dst max=0.305  (差 1.6%)
```
→ **线性插值音质损失可忽略。**

### 为什么 polyphase 在 A55 上这么慢
A55 没有向量浮点加速。polyphase 是「每相位 × 每抽头 × 每样本」的大量小数组
点积，cache 命中率极差。`np.interp` 是 C 实现单遍扫描，快两个数量级。

## 三、降采样：decimate3-mavg3 的真实抗混叠能力（我算过）

3 抽平均的频率响应 `|(1+2cos(2πf/sr))/3|`，在 48k 输入下：

| 频率 | 增益 | dB |
|---|---|---|
| 1000 Hz | 0.9943 | −0.0 |
| 4000 Hz | 0.9107 | −0.8 |
| **8000 Hz** | **0.6667** | **−3.5** ← Nyquist 边界 |
| 12000 Hz | 0.3333 | −9.5 |
| 16000 Hz | 0.0000 | −∞ |
| 20000 Hz | 0.2440 | −12.3 |

**混叠实测**（输入 1000 Hz + 20000 Hz，20000 会折叠到 4000）：

| 处理 | 1000Hz 幅度 | 4000Hz 混叠残留 |
|---|---|---|
| naive 抽取（无平均） | 4000 | **4000**（与原信号等强！） |
| **decimate3-mavg3** | 3977 | **976**（仅 24.4%） |

数学核对：`0.5 × gain(20000) = 0.5 × 0.244 = 0.122`，实测 976/4000 = 24.4%，**吻合**。

→ `decimate3-mavg3` 把 20 kHz 的混叠压到 **−12.3 dB**。有用，但**不是严格抗混叠**：
  在 8 kHz（Nyquist 边界）就已经 **−3.5 dB** 衰减，说明它也在吃掉有用的高频。

## 四、要不要换成正规低通？实测告诉你：不换

做了 A/B：同一段 48k 音频，分别用 `mavg3` 和 31 抽 sinc 低通（截止 7.2k）降采样，
再喂给同一个 ASR：

| 音频 | mavg3 | 正规低通 lpf31 | 耗时对比 |
|---|---|---|---|
| 0.wav | 昨天是 MONDAY TODAY IS THEY AFTER TOMORROW是星期三 | **完全相同** | 9.9ms vs 114.4ms |
| 1.wav | 这是第一种第二种叫呃与 ALWAYS什么 | **完全相同** | 4.0ms vs 55.8ms |
| 2.wav | 这是频繁的不认识记下来 FREQUENTLY平凡的 | 完全相同 | 3.6ms vs 51.2ms |

高频残留能量：`mavg3 / lpf31 = 13.7x`（0.wav）、`2.15x`（1.wav）
—— mavg3 确实漏下更多高频，**但识别结果一个字都没变**。

**结论：正规低通慢 11–14 倍，换不来任何识别收益。不换。**

## 五、最终选择

| 环节 | 算法 | 实测耗时 | 依据 |
|---|---|---|---|
| TTS 输出 22050→48000 | **linear** | 16.6 ms / 2s 音频 | 快 107 倍，频谱相关 0.9997 |
| 麦克风 48000→16000 | **decimate3-mavg3** | 3.6–9.9 ms / 段 | 与正规低通识别结果完全一致，快 11–14 倍 |

**两项都是"够用且最省"。** 重采样总开销相对 TTS 推理（RTF 1.40，2 秒音频要 2.8 秒）
只占约 0.6%，继续优化它没有意义。

## 六、真正该优化的是 TTS 推理本身

| 项 | 当前 | 如果优化到 |
|---|---|---|
| TTS RTF | 1.40 | 0.5 → 播报快 2.8 倍 |
| 重采样 | 16.6ms/2s | 已经到顶，收益 <0.6% |

要提速 TTS 只能靠：更好的模型 / NPU 加速 / 量化。**不是重采样能解决的。**
